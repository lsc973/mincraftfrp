# 家里连不进来怎么办

你想让朋友连上你家的服务器（Minecraft、远程桌面、网页……），但**外面根本
访问不到你这台机器**。这份文档讲怎么判断、以及怎么绕过去。

一句话结论：**用中继。** 中继模式下你家里完全不需要能被外部访问 —— 两边都是
主动连出去的，什么防火墙、运营商 NAT 都拦不住。

---

## 第一步：先确认你真的连不进来

别猜。两种地址分别查。

### IPv4：看光猫的 WAN 口地址

```bash
lanlink doctor
```

看「公网可达」那一项：

| 结果 | 含义 |
| --- | --- |
| WAN 口是 `100.64.x.x` ~ `100.127.x.x` | **运营商大内网（CGNAT）**。端口映射没用 —— 那个地址在电信/联通/移动自己的网里，外面路由不到 |
| WAN 口是 `10.x` / `172.16~31.x` / `192.168.x` | 多层 NAT，同样连不进来 |
| 是真正的公网地址 | IPv4 这条路通，路由器上做端口映射即可 |

> 国内家用宽带现在**绝大多数是 CGNAT**。光猫上那个「端口映射」页面填了也白填。

### IPv6：实测，别本机自测

IPv6 通常不做 NAT，很多人以为"有 IPv6 就等于能连"。**不一定** —— 光猫的
IPv6 防火墙默认挡掉所有入站。

**本机连自己永远是通的**（那是假阳性，证明不了任何事）。要找真正的外部节点测：

1. 在你要暴露的那台机器上开一个监听端口：
   ```bash
   lanlink tunnel --to 127.0.0.1:25565 --port 50001 --no-advertise
   ```
2. 浏览器打开 **https://www.tcptest.cn/tcping_ipv6**
3. 填 `[你的IPv6地址]:50001`（**方括号要带上**），点「单次测试」

结果一目了然：一堆国内节点全是红的，就是连不进来。

---

## 第二步：能改光猫就改，改不了别硬磕

如果你决定要试，先进**完整管理界面**：

| 入口 | 是什么 |
| --- | --- |
| `http://192.168.1.1` | 运营商定制 UI，安全设置基本被砍光 |
| `http://192.168.1.1:8080` | **华为经典界面**，功能完整（`telecomadmin` 登录） |

> 很多人卡在这里：`telecomadmin` 登进 80 端口那个界面，发现菜单跟普通账号
> 一模一样 —— 因为那个 UI 本来就没这些功能。**完整设置在 8080。**

进去之后：**安全 → 防火墙 → IPv6防火墙**。

### 但是：多半改不了

以华为 HN8145V（电信天翼网关）为例，那一页只有一项：

> ☐ 使能IPv6防火墙控制转发报文

**它是强制启用、锁死的，点不动。** 运营商在固件层面故意锁的，防止家用宽带
被当服务器。这种情况下管理界面里**没有任何办法**。

别在这上面耗太久。就算通过客服改成功了，光猫重新拨号、运营商推配置、
固件升级 —— 任何一个都可能把设置重置回去，到时候朋友又连不上。

---

## 第三步：搭一台中继

中继是一台**有公网 IP 的机器**，两边都主动连它，由它牵线。它只搬字节，
不需要认识你的游戏协议。

### 3.1 弄一台机器

推荐 **Oracle Cloud 的 Always Free**（永久免费）：

1. 注册 https://www.oracle.com/cloud/free/
   （要信用卡验证身份，选 Always Free 档**不会扣费**）
2. 创建实例：
   - 镜像：**Ubuntu 22.04 或 24.04**
   - 规格：**AMD 的 `VM.Standard.E2.1.Micro`**
   - 一定要传 **SSH 公钥**（建机器时会让传，不然登不进去）
3. 记下它的**公网 IP**

> **为什么选 AMD 那档、不选 ARM**：ARM（Ampere A1）看着配置高，但热门区域
> 长期满载，手动创建大概率报 "Out of capacity"，抢机器能耗掉你一下午。
> 而中继只是搬字节，1 核 1G 绰绰有余 —— AMD Micro 那档好开得多。

#### Oracle 的坑（按会卡住你的顺序）

**① 注册时千万别开 VPN / 代理。**

这是最容易踩、也最致命的一条。Oracle 的风控把"数据中心 IP"的权重拉得极高，
你用梯子反而**直接触发拒绝**。就用家里宽带直连。

**② 银行卡。**

- 要支持外币的卡（Visa / Mastercard）。单标银联卡通常过不了。
- **填的地址必须和卡的账单地址一致**，一个字都别改。
- 卡里留点余额 —— 会做一笔小额预授权验证（不扣钱）。
- 被拒的话打个电话给发卡行，说"我在订阅 Oracle 云服务，有一笔境外验证请放行"。

**③ 别反复重试。**

同一个设备/网络短时间内连续试，会被判定为风险叠加，越试越难。失败了
**等一天再试**，或者换台设备、换个网络（比如用手机热点）。

**④ 主区域选了就不能改。**

注册时选的 Home Region **一旦确定不可更改**，而且 Always Free 的资源
只能建在那个区域。所以第一步就要想清楚。

国内用户一般选：**东京 / 大阪 / 首尔 / 新加坡**（离得近，延迟低）。

**⑤ 主区域里可能开不出机器。**

如果目标区域提示容量不足，别死磕 —— 注册时换个区域重来（这也是唯一
能换区域的机会），或者挑人少的时段（国内时间凌晨）再试。

**⑥ 空闲会被回收。**

Oracle 会回收"长期空闲"的 Always Free 实例。中继平时没什么流量，
有被判定成空闲的风险。**偶尔开一次房间用一用**，或者在上面跑个
定时任务制造一点活动，能降低概率。

**⑦ 别把唯一的东西放这儿。**

免费层适合当"副驾"，不适合当生产主力。中继挂了重建一次也就几分钟
（`tools/deploy_relay.sh` 跑一遍的事），但心里要有这个预期。

> **其他选择**：腾讯云/阿里云的轻量应用服务器。要花钱（新用户活动价
> 一年几十块），但注册用微信/支付宝几分钟搞定，国内节点延迟也低。
> 中继很轻，最便宜的配置都够。流量包注意别选太小的。

### 3.2 ⚠️ 放行端口（最容易漏的一步）

**Oracle 默认把所有端口都关着**，很多人卡在这里，以为中继没跑起来。

在 Oracle 控制台：

**实例详情 → 主 VNIC → 子网 → 安全列表 → 添加入站规则**

| 字段 | 值 |
| --- | --- |
| 源类型 | CIDR |
| 源 CIDR | `0.0.0.0/0` |
| IP 协议 | TCP |
| 目标端口范围 | `9000` |

**光改安全列表还不够**，Ubuntu 里还有一层自带的防火墙（iptables）：

```bash
sudo iptables -I INPUT -p tcp --dport 9000 -j ACCEPT
sudo netfilter-persistent save
```

> 云服务器厂商（腾讯云/阿里云）的叫法不同：安全组 / 防火墙规则，道理一样。

### 3.3 把中继跑起来

**一条命令搞定**（推荐）：脚本会把账号、代码、口令文件、systemd 服务、
本机防火墙全配好，最后启动并验证一遍。

```bash
git clone https://github.com/lsc973/mincraftfrp.git
cd mincraftfrp
sudo bash tools/deploy_relay.sh
```

没给 `--token` 的话它会**自动生成一个口令并打出来** —— 记下来，
打包给对面的 exe 时要用。

```
sudo bash tools/deploy_relay.sh --token 你的口令 --port 9000
```

脚本跑完会提醒你**去云控制台放行端口**（就是上面 3.2 那步，脚本改不了控制台）。

重复跑是安全的：已经有的东西会跳过。**它默认不会覆盖已有的口令** ——
换了口令而没重新打包的话，对面手上那个 exe 就对不上了。确实要换就加
`--force-token`，然后重新打包给对面。

---

**手动做也行。** 项目是**纯标准库**的，Ubuntu 自带的 Python 3 就够，
不用装任何依赖：

```bash
git clone https://github.com/lsc973/mincraftfrp.git
cd mincraftfrp

# 先用前台跑一下，确认没问题
python3 -m lanlink relay --bind 0.0.0.0 --port 9000 --token 你的口令
```

看到 `中继已启动` 就成了。systemd 那步见 3.4。

**验证**：在**另一台机器**上跑

```bash
lanlink-cli.exe list --relay 服务器IP:9000
```

能列出「中继 xxx 上的房间：（没有）」就说明端口通了。

### 3.4 设成开机自启（手动做的话看这节）

> 用 3.3 那个脚本的话，这一步已经做完了，可以跳过。

仓库里有现成的 systemd 单元。不想打包二进制的话，直接把 `python3 -m lanlink`
包一层脚本也行：

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin lanlink
sudo install -d -o lanlink -g lanlink /opt/lanlink /etc/lanlink
sudo cp -r lanlink /opt/lanlink/
sudo sh -c 'echo "你的口令" > /etc/lanlink/token'
sudo chown lanlink:lanlink /etc/lanlink/token
sudo chmod 600 /etc/lanlink/token
```

把 `ExecStart` 改成：

```
ExecStart=/usr/bin/python3 -m lanlink relay --bind 0.0.0.0 --port 9000 --token-file /etc/lanlink/token --log-level INFO
```

（`WorkingDirectory` 设成 `/opt/lanlink`）

```bash
sudo cp packaging/systemd/lanlink-relay.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now lanlink-relay
systemctl status lanlink-relay
```

口令走 `--token-file` 而不是 `--token`：命令行参数会出现在 `ps` 输出里，
谁都看得见。

## 第四步：打包给对面的 exe

把中继地址**编进 exe**，对面就只要填房间号和口令：

```bash
python packaging/build.py --mode gui ^
  --server-relay 服务器IP:9000 ^
  --relay-token 你的口令 ^
  --label "给小明的"

python tools/make_release.py --label "给小明的"
```

（Linux/macOS 上用 `\` 续行）

产出 `release/lanlink-给小明的.zip` —— 里面是 exe 加一份自动生成的
`使用说明.txt`。**直接发过去就行。**

> 用 GitHub Actions 出包更省事：仓库页面 → Actions → 「打包 exe」→ Run workflow，
> 填上中继地址和口令。详见 README 的「自动打包」一节。

## 第五步：开房

你这头：

```bash
lanlink-cli.exe tunnel --to 127.0.0.1:25565 --password 你设的口令
```

**不用填任何地址** —— 中继地址已经编进去了，启动时会自动挂上去。

它会打出一段话，复制发给对面：

```
lanlink 隧道已开好。对方只要填房间号和口令就能连，不用知道地址：

【命令行版】把下面这一行整个复制到终端里回车：
  lanlink-cli.exe tunnel --room 2afb97a0 --password pw123 --listen 25565

【图形版】打开 lanlink.exe → 端口转发隧道 → 选「服务在对面」，填：
  房间号：2afb97a0
  房间密码：pw123
```

对面双击 exe → 端口转发隧道 → 选「服务在对面」→ 填房间号和口令 → 启动。
然后在游戏里连 `127.0.0.1:25565` 就等于连到了你家。

## 排查

| 现象 | 多半是什么 |
| --- | --- |
| 你这头提示「连接中继超时」 | 中继没跑起来，或者**云服务器的安全列表/安全组没放行端口**（Oracle 最容易漏这个） |
| 对面提示「房间号不对」 | 抄错了。房间号是 8 位十六进制，注意别把 `0` 和 `O` 看混 |
| 两边都显示"就绪"但游戏连不上 | 检查游戏里连的是不是 `127.0.0.1:25565`；或者服务端那台机器的服务本身没开 |
| 玩一会儿断线 | 看中继的日志：`journalctl -u lanlink-relay -f` |
| 中继被人白嫖 | 加口令（`--token`），打包时用 `--relay-token` 编进去 |

---

## 为什么不用 Tailscale / ZeroTier

它们也能解决这个问题，而且更好用。**唯一的区别是对面要装东西**：

- Tailscale / ZeroTier：两边都装客户端，之后像在同一局域网
- 这份文档的方案：对面只跑一个 exe，什么都不用装、不用注册

如果"对面不想装任何东西"这个约束不重要，那就用 Tailscale —— 比自建中继省事得多。
